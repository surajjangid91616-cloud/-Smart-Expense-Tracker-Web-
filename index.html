    Why tracking spending fails

    Most people stop logging small purchases within weeks. Three gaps cause it.

    Logging is tedious

    Micro-transactions go unrecorded, so personal spending is never fully visible.

    Paper bills stay on paper

    Retail receipts are separate from the database, so their details never reach the ledger.

    Apps report after the fact

    Current tools summarize what you already spent instead of warning you before you overspend.

    From receipt to warning in four steps

    Capture

    Upload a photo of a bill, or fill in the manual form on the dashboard.

    Extract

    The OCR engine pulls out the merchant, date and total.

    Store

    Verified transactions are saved as documents in MongoDB.

    Refresh

    Charts update at once and flag any category nearing its cap.

    Objective and scope

    Build a cross-platform progressive web app that makes personal transaction auditing simple through optical scanning, automatic ledger sync and early budget warnings.

    Built for university students, gig professionals and small household administrators who want clear, low-effort balance monitoring on any device.

    What users get

    • Less typing. OCR fills in the ledger entry for you.
    • Spending guardrails. Visual analytics show when a monthly cap is close.
    • Clearer audits. Odd subscriptions and money leaks stand out.
    • Room to grow. The web app can later extend to native mobile.

    Known limitations

    The first release has clear boundaries.

    • Image quality. OCR accuracy drops with blur, odd angles or crumpled bills.
    • Needs internet. Entries can be cached offline, but sync and budget updates wait for a connection.
    • Local currency only. Real-time foreign currency conversion is not included yet.

    How it will be tested

    Unit tests

    Jest · React Testing Library

    Check components, math helpers and chart data adapters.

    API tests

    Postman · Supertest

    Check login paths, token headers and payload formats against the database schema.

    End-to-end tests

    Cypress · Playwright

    Replay real user flows: receipt upload, form entry and navigation.

    Conclusion

    Automatic receipt extraction plus visible budget limits solves the main pain points of personal budgeting. The microservice-style architecture leaves room for more financial features later.
